# 项目概览

## 背景

PlugHub 是面向 Revit 2020 的模块化插件框架。项目由旧仓库和旧命名整理而来，目标是把零散 Revit 工具收拢到一个可治理、可扩展的入口中。

框架层只负责模块契约、配置加载、模块发现、启用/禁用、排序组合、诊断和 Revit 2020 入口适配。具体 Revit 业务操作放在外部模块中实现，主框架不再包含内置业务功能。

## 目标

- 统一 Revit Ribbon 入口，使用 `PlugHub` tab 和单一 `workspace` 工作台。
- 通过配置管理模块和功能，支持启用、禁用、隐藏、重命名、排序、图标和按钮大小。
- 支持从 `sources.json`、`packages/dropins`、指定本地文件夹和 GitHub 仓库读取插件包清单。
- 将框架层与 Revit API 业务命令隔离，降低后续模块接入成本。
- 保留静态验证，防止旧命名、内置业务模块、过期面板和错误分层回流。

## 开发思路

- **配置优先：** 模块、功能、来源、分组和排序都先落到 JSON 配置，再由运行时组合成 Ribbon。
- **单工作台：** 取消视图集思路，只保留一个 `workspace`，用 group/category/tag 组织功能。
- **Revit 推荐入口：** 顶部入口使用 Ribbon；设置、状态、功能反馈使用 WPF 窗口，不使用 DockablePane 或 WinForms。
- **结构变更明确提示：** 模块/功能开关尽量在命令执行前读取最新状态；Ribbon panel、按钮新增/删除、图标和大小仍需重启 Revit 重新渲染。
- **验证驱动整理：** 每次移除旧方案时，同步更新 `PlugHub.StaticValidation`，让验证器覆盖关键约束。

## 当前进度

截至 2026-05-28，当前主线状态如下：

- 项目名称、程序集元数据、addin 发布者已统一为 PlugHub / GAOMENGGU。
- 默认运行配置不包含任何业务模块或功能。
- 旧内置业务模块已从主框架分离，两个功能拆为外部独立模块项目：
  - `PlugHub.DuctPreferredJunction`：切换风管 Tee/Tap 首选连接。
  - `PlugHub.FamilyMaterialParameters`：批量添加并关联族材质参数。
- 样例模块、空白模块、占位功能、旧 workspace group 和内置业务模块已从源码、配置、文档和部署产物中移除。
- 设置窗口支持插件包/功能开关、显示名、所属分组、图标、大小和拖拽排序；新增业务模块和功能放到外部模块项目中完成。
- 插件包来源支持 `packages/dropins`、指定本地文件夹和 GitHub 仓库缓存/拉取。
- 默认图标由代码生成，功能未配置 `iconPath` 时仍能显示小图标和大图标。
- Revit 2020 构建输出固定到 `dist\Revit2020`。

## 已知边界

- 当前非 Revit 环境只能做 C# 静态验证和本机构建，不能替代 Revit 实机测试。
- .NET Framework 已加载程序集不能真正热卸载；新增模块程序集、二进制替换和 Ribbon 结构类变更需要重启 Revit。
- 框架不提供插件市场、授权、自动更新服务或远程执行能力。
- 设置页不创建空模块或空功能；新增业务能力应在外部插件包项目中完成。

## 后续优先级

- 增加 Revit 2020 实机验收记录模板，明确模型副本、族文件副本和人工检查步骤。
